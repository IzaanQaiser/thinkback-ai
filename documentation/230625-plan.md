### **Phase 1: Backend API Construction & Testing**

**Goal:** To build a robust and secure set of API endpoints for managing user data. At the end of this phase, we will have a fully functional backend, testable from the command line, without having touched the frontend UI.

*   **Step 1.1: Define Data Models**
    *   I will create Pydantic models in `backend/router.py` to define the structure for `Entry`, `Collection`, and `Category`. This ensures our data is always consistent.

*   **Step 1.2: Implement Endpoints for "Entries"**
    *   **`POST /api/entries`**: Creates a new entry. It will extract the user's ID from their authentication token and save the entry to a private subcollection in Firestore (`users/{uid}/entries`).
    *   **`GET /api/entries`**: Fetches all entries belonging to the currently logged-in user.
    *   **`PUT /api/entries/{entry_id}`**: Updates an existing entry.
    *   **`DELETE /api/entries/{entry_id}`**: Deletes a specific entry.

*   **Step 1.3: Implement Endpoints for "Collections"**
    *   We will mirror the process from Step 1.2 to create a full set of endpoints (`POST`, `GET`, `PUT`, `DELETE`) for managing user-created collections.

*   **Step 1.4: Testing and Verification**
    *   After implementing each set of endpoints, I will guide you on how to test them directly using `curl` commands in the terminal. This verifies that our backend logic is solid before we proceed.

### **Phase 2: Frontend Integration**

**Goal:** To connect our React frontend to the new backend API, replacing all hardcoded mock data and building the UI for user interaction.

*   **Step 2.1: Create an API Service Layer**
    *   I will add new functions to `frontend/src/services/api.ts` (e.g., `getEntries`, `createEntry`). These functions will handle all communication with the backend, keeping our components clean.

*   **Step 2.2: Fetch and Display User Data**
    *   In the `DashboardPage.tsx`, I will remove the mock data import.

*   **Step 2.3: Build Creation and Editing UI**
    *   I will create the necessary forms and modals that allow users to create, view, and edit their entries and collections.
